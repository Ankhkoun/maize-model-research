# E2-WPEonly Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a frozen E2-WPEonly experiment whose sole architectural difference from E0 is content-only five-point Mexican-hat WPE before the existing calendar DOY lookup addition.

**Architecture:** Reuse `FivePointMexicanHatWaveletEncoding` and the common trainer. Add one explicit model-routing case for `doy_lookup` plus five-point WPE, a frozen YAML configuration, and an allow-listed formal training output. Preserve the legacy E1 WPE and E2-W learned-slot routes byte-for-byte in behavior.

**Tech Stack:** Python 3.11, PyTorch 2.10, PyYAML, pytest, CUDA AMP.

## Global Constraints

- Formal experiment ID is exactly `E2-WPEonly`; status remains `not_run`.
- Do not load or evaluate Test and do not register an E2-WPEonly frozen Test asset.
- Do not start formal training without a separate explicit user approval.
- Do not stage, commit, push, switch/create branches, or create a PR.
- E2-WPEonly uses E0 data, loss, optimizer, schedule, seed, manifest, normalization, and Validation selection policy unchanged.
- WPE receives content-only `patch_tokens`; DOY is added only after the WPE result; class tokens never enter WPE.
